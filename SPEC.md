# Stratix Core — Spec

## What this is
REST API backend for Stratix, a task management app targeting App Store
publication. Built in Go using a modular monolith with Clean Architecture.

## Stack
- Language: Go 1.22+
- Framework: Echo v4
- Database: PostgreSQL (Neon) via pgx/v5 + sqlc
- Storage: Cloudflare R2 (S3-compatible)
- Hosting: Koyeb
- LLM: Anthropic Claude (natural language task parsing)
- Auth: JWT — 15min access tokens + 30day rotatable refresh tokens

## Architecture
Modular monolith. Four bounded contexts:
- auth        → registration, login, JWT issue/refresh/revoke
- tasks       → CRUD, recurrence, status transitions, attachments
- analytics   → read-only reporting (summary, streaks, type distribution)
- notifications → push (FCM/APNs), device token management
- ai          → natural language task parsing via Claude API

Each module: handler → service → repository (Clean Architecture).
Modules never import each other — cross-module communication only
through internal/events/dispatcher.go (in-process async event bus).

## Domain rules (non-negotiable)
- Log tasks have no Status, no Priority, no Schedule — only Pinned/Archived
- All other types default to Status=Backlog, Priority=Medium, Occurrence=Once
- Status transitions follow a strict state machine (see internal/domain/task.go)
- task.Complete() must be used (not SetStatus) so TaskCompletedEvent fires
- DuePassed is computed on read — never persisted to the database
- Recurrence instances are generated lazily (on calendar query), not upfront
- Domain IDs are generated by the domain (uuid.New()), not the database

## Repository rules
- Repository implementations must translate pgx.ErrNoRows → domain.NotFoundError
- Unique constraint violations (pgErr.Code == "23505") → domain.ConflictError
- Service layer never sees pgx errors — only domain errors and apperror types
- All list queries fetch limit+1 rows for cursor pagination

## API design
- REST, versioned at /v1
- Cursor-based pagination (not offset)
- All datetimes in UTC, ISO8601
- Error shape: {"error": {"code": 404, "message": "task not found"}}
- Auth endpoints: public (no JWT)
- All other endpoints: protected (Bearer JWT required)
